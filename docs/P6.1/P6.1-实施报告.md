# NodePoolME P6.1 实施报告

## 一、结论

P6.1「最终优选结果与版本快照」已完成。本批在 P1–P5 已验收逻辑之上新增只读旁路：

- 从 P5 六类竞争当前 `preferred` 状态汇总最终优选结果；
- 建立当前优选结果的待定订阅池（内部结果，不等于实际发布订阅）；
- 每次有效变化生成独立、不可篡改的版本快照；
- 按类别分别记录新增、移除、保留，支持当前版本与上一有效版本追溯；
- 提供只读查询接口、后台页面和 Dashboard 联动；
- 未实施关键词过滤、订阅生成/发布和 P6.2/P7。

版本：`v2.044`。

## 二、交付范围

### 1. 六类最终优选

独立维护标准综合、GPT、YouTube、Telegram、GitHub、国外综合六类结果。每类直接投影 P5 对应类别的 `state='preferred'` 节点：

- 六类相互独立，不互相覆盖；
- 同一节点允许同时出现在多个类别；
- 不设置固定数量，不补位、不凑数；
- 健康池、观察池、候选状态不会进入最终优选；
- 不修改 P1–P5 状态、评分、资格与竞争规则。

### 2. 待定订阅池

当前版本的全部 `np6_entries` 即内部待定订阅池，完整承载 P5 已选优选节点。该池：

- 不等于健康池；
- 不等于实际发布订阅；
- 不做关键词过滤；
- 后续过滤只能发生在最终下发出口，不能反向修改优选结果或历史快照。

### 3. 版本与快照

每个有效版本记录：版本号、生成时间、触发原因、六类完整名单、类别计数、新增/移除/保留、是否为空、有效状态、上一版本、来源 P5 轮次、成员签名。

版本规则：

1. 只有 P5 最近一轮竞争 `success` 且已产生有效优选结果时才允许生成版本；
2. 成员签名未变化时不生成新版本；
3. `running` / `partial` / 无 P5 轮次时拒绝生成，保留上一有效版本；
4. P5 成功且确实无 `preferred` 节点时，生成有效空版本，不继承旧节点；
5. 历史版本只追加，不更新、不删除；
6. 所有查询接口只读，不因刷新或重复拉取生成版本。

### 4. 自动更新

新增独立调度任务 `job_final_p6`，每 5 分钟检查一次。仅在：

- P5 最近一轮为 `success`；
- 当前优选成员签名与最新版本不同；

时生成新版本。页面同时提供「同步当前优选」手动入口。自动调度可通过环境变量 `NODEPOOL_P6_SCHEDULER=0` 关闭，不影响 P1–P5。

## 三、后台页面

新增「最终优选」页面 `/final`，侧栏编号 09，后续菜单顺延：

- 六类优选数量与总量；
- 当前有效版本号、生成时间、触发原因、来源 P5 轮次；
- 本次新增 / 移除 / 保留数量；
- 六类节点完整名单（名称、机场、分数、P80）与当前分类明细表；
- 历史版本列表；
- 当前版本与上一版本按类别分列的差异；
- 有效空版本、待同步、P5 未成功等状态提示；
- 桌面表格 + 移动卡片两套布局。

Dashboard 新增独立「最终优选结果 · P6.1」面板，展示总量、版本号、生成时间、标准/五类业务计数、同步状态，不改变原 P1–P5 统计。

## 四、接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/final/summary` | 当前版本摘要、六类计数、历史数量、P5 源状态、可同步状态 |
| GET | `/api/final/current` | 当前版本 + 六类完整名单 + 差异；`category` 可只取一类 |
| GET | `/api/final/versions` | 历史版本列表，`limit` 默认 30、上限 100 |
| GET | `/api/final/versions/{id}` | 指定版本详情；`category` 可只取一类 |
| GET | `/api/final/diff` | 当前版本对上一有效版本差异；`version_id` 可指定历史版本 |
| POST | `/api/final/snapshot` | 手动同步；只生成版本，不发布订阅 |

所有 GET 接口只读；`POST /snapshot` 是唯一版本生成入口。

## 五、严格边界

- 订阅发布入口或客户端拉取接口；
