# P6.2.2 统一订阅数据流与格式说明

- 版本：v2.047
- 适用批次：P6.2.2
- 定位：说明统一订阅从哪里取数、如何合并/过滤/命名、如何生成四种格式，以及版本与历史记录如何绑定

## 一、端到端数据流

```text
机场采集
→ P1 原始节点池
→ P2 基础健康检测
→ P3 业务专项检测
→ P4 七天质量与下载速度评价
→ P5 六类智能节点竞争
→ P6.1 六类最终优选版本（唯一节点选择来源）
→ P6.2.2 六类合并 + 稳定 node_id 去重
→ P6.2.1 当前规则 + 当前版本关键词过滤（唯一过滤来源）
→ GPT / YT / TG / GH 服务标签
→ 统一展示名
→ 四格式兼容性预检
→ Clash / sing-box / Base64 / Loon 同一集合输出
```

P6.2.2 不接入 P1 采集、P2/P3/P4 检测、P5 竞争或旧发布链，只读取已完成结果。P1 的 `np_nodes` 只用于按稳定 `node_id` 补全 `protocol/params`；节点选择、服务器、端口、机场、评分和名称来自 P6.1。

## 二、来源表与读取入口

| 来源 | 读取内容 | 用途 |
| --- | --- | --- |
| `np6_versions` / `np6_entries` | 当前版本、六类条目 | 合并与去重、标签、节点基础信息 |
| `np621_state` / `np621_results` | 当前修订号、当前预览、命中原因 | 关键词过滤与版本闸门 |
| `np_nodes` | `protocol`、`params` | 仅补全协议参数，不参与选点 |
| `np622_batches` | 批次汇总 | 概况、历史、Dashboard |
| `np622_outputs` | 四格式状态与内容 | 预览、下载、SHA/字节 |
| `np622_nodes` | 批次节点快照 | 管理预览、被过滤/不兼容节点追溯 |

## 三、合并与去重

1. 对六类 `np6_entries` 取并集。
2. 以 `node_id` 为唯一键聚合；同名不同 ID 不合并。
3. 同一节点跨类出现时，`categories`、`labels`、命中原因取并集，只输出一次。
4. 不固定数量、不补位；六类全空时仍可生成空批次。
5. 合并只读，不修改 P5 状态、P6.1 条目和版本。

批次字段记录：

- `merged_count`：合并前记录数；
- `unique_count`：稳定 ID 去重后节点数；
- `duplicate_count = merged_count - unique_count`；
- `category_counts_json`：六类各自数量。

## 四、业务标签与展示名

只认 P6.1 六类：`gpt→GPT`、`youtube→YT`、`telegram→TG`、`github→GH`。`standard`、`global` 不产生标签。顺序固定 `GPT→YT→TG→GH`，去重后拼接。

展示名：

```text
速度等级 emoji + 机场名 + "·" + 标签段 + "·" + P6.1 原始节点名
```

无标签时省略标签段。P6.1 原始名称不改。若两个不同节点的最终展示名完全相同，只对后一个展示名追加 ` #2`、` #3`，确保客户端不因重名吞节点。

## 五、P6.2.1 过滤绑定

不重新实现关键词匹配，只消费当前 `np621_results`：

- 版本：`p6_version_id` 必须等于当前 P6.1 `version_id`；
- 修订：`rule_revision` 必须等于 `np621_state.rule_revision`；
- 完整性：合并节点必须能在结果中找到；
- 同一节点跨类命中时，`reason` 取并集，保留 `rule_id`、`keyword`、`field`、`field_label`、`value`。

命中节点：

- `status=filtered`；
- 不进入任何客户端内容；
- 仍在 `np622_nodes` 和管理预览中保留标签、分数、命中原因；
- 不撤销 P5/P6.1 资格。

## 六、格式兼容性预检

因为四种格式共用同一集合，先检查节点是否能被四种格式同时表达。任一格式不支持时，节点统一排除，不进入 `output`。

记录：

- `compatibility_excluded_count`；
- `unsupported_json.count/reasons/nodes`；
- 节点 `status=unsupported`；
- 页面“格式不兼容”及逐格式原因。

常见原因包括 Loon 不支持某协议/传输/加密、sing-box 无 SSR outbound、端点无效等。排除是明确记录的不支持，不是伪造转换，也不是某格式静默少节点。

## 七、四格式实现

| 格式 | 实现 | 结构 | 校验 |
| --- | --- | --- | --- |
| Clash / Mihomo | `parser.clash_proxy` + 统一补全 | `proxies`、`proxy-groups`、`rules` | YAML 可解析、数量与名称集合一致 |
| sing-box | `parser.singbox_outbound` + 统一 TLS/传输补全 | `log/dns/inbounds/outbounds/route` | JSON 可解析、节点 outbound 数量与 tag 一致 |
| Base64 | `parser.to_uri` 生成链接后 Base64 | 每行一个节点 URI | 行数一致、片段名称解码一致 |
| Loon | 复用 `builder.build_loon` | Loon URI 文本 | 非注释行数一致、URI 协议前缀合法 |

四格式节点顺序、`display_name`、数量完全一致；分别独立记录状态、字节、SHA256 和失败原因。

## 八、状态与失败

节点：

- `allowed`：通过过滤且格式兼容；
- `filtered`：关键词命中；
- `unsupported`：格式不兼容。

批次：

- `success`：输出非空，四格式均成功；
- `partial`：至少一个格式失败，另有成功格式；
- `failed`：四格式全部失败；
- `empty`：允许候选为空且四格式成功生成空结构；
- `stale`：页面派生状态，批次绑定的 P6.1 版本或规则修订已不是当前值。

格式失败必须写真实 `failure_reason`，内容不写入伪造节点；下载失败格式返回错误。

## 九、表结构

`id,batch_no,created_at,trigger,p6_version_id,p6_version_no,p621_revision,p621_computed_at,category_counts_json,merged_count,unique_count,duplicate_count,filtered_count,candidate_count,compatibility_excluded_count,output_count,gpt_count,yt_count,tg_count,gh_count,multi_label_count,is_empty,status,status_reason,unsupported_json,node_set_sha256`

### 9.2 `np622_outputs`

`id,batch_id,format,status,node_count,generated_at,p6_version_id,p6_version_no,p621_revision,content_sha256,content_bytes,content_text,failure_reason`

唯一键 `(batch_id, format)`；每批四行，状态独立。

### 9.3 `np622_nodes`

`batch_id,node_id,node_name,airport_id,airport_name,server,port,protocol,speed_grade,display_name,labels_json,categories_json,status,hits_json,unsupported_json,score,p80_ms`

主键 `(batch_id, node_id)`；保存批次时点快照，后续源数据变化不覆盖历史。

### 9.4 `np622_events`

`id,at,event,batch_id,detail_json`；记录批次生成事件。

## 十、API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/unified-subscription/summary` | 概况、当前合并结果、批次、四格式、节点 |
| GET | `/api/unified-subscription/history?limit=` | 追加式批次历史与 stale 标记 |
| GET | `/api/unified-subscription/formats/{fmt}?batch_id=` | 指定/最新批次格式内容 |
| POST | `/api/unified-subscription/generate` | 新建批次并生成四格式 |
| GET | `/api/unified-subscription/download/{fmt}` | 登录保护的管理员附件下载；stale 返回 409 |

格式键：`clash,singbox,base64,loon`。

文件名：`nodepool-unified.yaml`、`nodepool-unified.json`、`nodepool-unified.base64.txt`、`nodepool-unified.loon.txt`。

下载响应带 `Content-Disposition: attachment`、`X-NodePoolME-Batch`、`X-NodePoolME-Nodes`、`Cache-Control: no-store`。

## 十一、历史与版本解释

- 每次生成新批次，绝不覆盖旧批次或旧输出。
- 四格式同批关联，可查看对应 P6.1 版本、规则修订、格式、数量和生成时间。
- 重复生成不触发 P2/P3/P4/P5，不创建 P6.1 版本。
- 旧批次在版本/规则变化后只标记 `stale`，不自动删除；管理员仍可追溯其内容，但不能下载为当前订阅。
- 批次不保存机场原始订阅 URL 或上游凭据；订阅内容只含节点必需字段。

## 十二、页面与统计映射

页面总菜单 14 项，统一订阅为第 11 项，路由 `/unified-subscription`：

- 概况四联：合并记录、稳定 ID、过滤、输出；
- 六类卡：standard/gpt/youtube/telegram/github/global；
- 标签卡：GPT/YT/TG/GH/多标签；
- 格式卡：四格式 tab、状态、数量、时间、P6.1/规则、SHA、内容、下载；
- 节点表：允许、过滤、不兼容三种状态；
- 批次表：每批四格式独立状态。

Dashboard `unified_subscription` 字段：

`status,nodes,filtered,labels{gpt,yt,tg,gh},last_generated,stale,p6_version_no,revision,formats{clash,singbox,base64,loon}`

全部来自数据库当前批次。
