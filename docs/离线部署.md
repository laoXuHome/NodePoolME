# NodePoolME 离线部署（linux/amd64）

离线包含：`nodepoolme-<tag>-amd64.tar` 镜像归档、`docker-compose.yml`、`.env.example`、`README.md`、`Dockerfile` 和本说明。

## 1. 解压与导入镜像

```bash
mkdir -p /opt/nodepool/{data,config,logs,backup,state}
cd /opt/nodepool
tar -xzf /path/to/nodepoolme-<tag>-offline-amd64.tar.gz
docker load -i nodepoolme-<tag>-amd64.tar
docker image inspect ghcr.io/laoxuhome/nodepoolme:<tag> --format '{{.Id}}'
```

镜像归档保留原始 tag：`ghcr.io/laoxuhome/nodepoolme:<tag>`。不要重新打 `latest`，否则无法确认实际版本。

## 2. 准备目录

```bash
cd /opt/nodepool
cp .env.example ./.env
chmod 600 .env
vi .env
```

至少修改：

```bash
NODEPOOL_ROOT=/opt/nodepool
NODEPOOL_IMAGE=ghcr.io/laoxuhome/nodepoolme:<tag>
NODEPOOL_ADMIN_PASSWORD=<强密码>
NODEPOOL_SECRET=<随机长字符串>
NODEPOOL_TZ=Asia/Shanghai
```

## 3. 启动（不要 pull）

离线主机没有 GHCR 访问能力，启动时跳过拉取：

```bash
cd /opt/nodepool
docker compose up -d --pull never
docker compose ps
curl -fsS http://127.0.0.1:8080/healthz
```

`--pull never` 强制使用已导入的本地镜像。正常返回中应包含：

```json
{"status":"ok","version":"2.001","engine":"mihomo","db":true,"scheduler":true,"migration":"INACTIVE"}
```

## 4. 更新离线包

```bash
cd /opt/nodepool
docker exec nodepool python -m backend.database.cli backup --label pre-upgrade --json
docker compose stop nodepool
docker load -i /path/to/nodepoolme-<新tag>-amd64.tar
# 修改 .env 的 NODEPOOL_IMAGE 为新 tag
docker compose up -d --pull never
```

如果状态显示迁移待执行，先按 README 的停机迁移流程执行，再启动应用。

## 5. 数据目录

`data/`、`config/`、`logs/`、`backup/`、`state/` 五个目录必须保留。`state/` 必须与数据库同文件系统，且不能位于 `data/` 内。删除 `state/` 会丢失维护态证据。
