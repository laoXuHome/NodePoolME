# P6.2.2-R1 数据结构与状态说明

- 版本：v2.048
- 适用模块：`backend/unified_subscription/`
- 目标：补齐统一订阅批次的完整连接配置快照、指纹与 stale 判定数据结构

## 一、设计原则

1. 节点选择仍只来自 P6.1，关键词过滤仍只来自 P6.2.1。
2. P1 `np_nodes` 只读提供当前 `protocol/server/port/params`，不参与选点，不写回。
3. 连接配置在生成时冻结，批次与节点快照绑定；历史批次不随后续 P1 数据变化。
4. 单节点指纹和批次总指纹共同表达“本批实际使用的连接配置”。
5. stale 是派生状态，不覆盖历史批次原始状态；历史批次仍保留原状态、原内容和原配置。
6. 敏感连接参数只保存在节点快照和订阅文件内容中，不进入普通列表、Dashboard、历史摘要或事件日志。

## 二、表结构增量

### 2.1 `np622_batches` 新增

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `config_sha256` | TEXT | 本批全部快照节点连接配置总指纹 |
| `config_node_count` | INTEGER | 参与总指纹计算的节点数，包含 filtered/unsupported |

已有字段保持不变。`node_set_sha256` 仍表达最终输出节点集合与展示名，不替代连接配置指纹。

### 2.2 `np622_nodes` 新增

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `params_json` | TEXT | 生成时冻结的完整有效连接参数（含客户端连接必需参数） |
| `config_sha256` | TEXT | 该节点 `protocol/server/port/params` 的稳定指纹 |

主键仍为 `(batch_id, node_id)`。同一稳定节点在不同批次各自保存独立快照；新批次不更新旧批次行。

### 2.3 迁移兼容

`store.ensure_schema()` 在创建表后检查 `PRAGMA table_info`，对 v2.047 及更早数据库追加 R1 字段：

- 旧 `np622_batches` 得到 `config_sha256=NULL`、`config_node_count=0`；
- 旧 `np622_nodes` 得到 `params_json=NULL`、`config_sha256=NULL`。

旧批次因此被识别为 `config_snapshot_missing` 并标记 stale，不允许继续下载；历史内容仍保留可追溯。

## 三、连接配置与指纹

### 3.1 单节点配置

```json
{
  "protocol": "vless",
  "server": "10.0.0.3",
  "port": 443,
  "params": {
    "uuid": "...",
    "network": "ws",
    "security": "reality",
    "sni": "reality.example.com",
    "publicKey": "...",
    "shortId": "...",
    "fingerprint": "chrome"
  }
}
```

`params` 保存生成时的有效连接参数。普通 API 的 `node_payload` 不返回该字段。

### 3.2 规范化

- `protocol`：去首尾空格、转小写；
- `server`：去首尾空格；
- `port`：转整数，无法解析记 0；
- `params`：递归按键排序；`null` 和空字符串不进入指纹；字符串保留原始大小写和内部空格，避免把密码、UUID、路径误规范化；
- JSON 使用 `sort_keys=True`、紧凑分隔符、`ensure_ascii=False`，保证同值不同键序不产生不同指纹。

### 3.3 指纹

```text
node.config_sha256 = SHA256(canonical(protocol, server, port, params))

batch.config_sha256 = SHA256(
  "\n".join(f"{node_id}:{node.config_sha256}" for node_id in ascending order)
)
```

覆盖范围包括协议、服务器、端口、密码、UUID、TLS、Reality、WebSocket/gRPC/H2、SS 加密与插件等全部有效参数。任一值变化都会改变指纹。

## 四、生成流程

1. `_make_snapshot()` 校验 P6.1 当前版本和 P6.2.1 当前预览/修订号。
2. 读取 P6.1 六类条目，按稳定 `node_id` 合并。
3. 读取 P6.2.1 结果并合并命中原因。
4. 按稳定 `node_id` 只读查询 P1 `protocol/server/port/params`。
5. 规范化参数，计算每个节点 `config_sha256`。
6. 若存在当前 P1 连接配置缺失，`generate()` 返回 `node_config_missing`，禁止生成。
7. 计算批次 `config_sha256` 和 `config_node_count`。
8. 四格式兼容性预检，形成统一 `output`。
9. 四格式分别生成、校验、记录状态。
10. 在同一事务内写入 `np622_batches`、四行 `np622_outputs`、全部 `np622_nodes` 和事件。

重复生成永远新增批次，不更新历史批次。

## 五、stale 判定顺序

`_batch_stale_details()` 返回：

```json
{
  "stale": true,
  "codes": ["p6_version_changed", "node_config_changed"],
  "code": "p6_version_changed",
  "reason": "P6.1 最终优选版本已变化；3 个节点的连接配置已变化，请重新生成统一订阅。",
  "config_changed_count": 3,
  "config_changed_node_ids": [1, 2, 3],
  "config_missing_count": 0,
  "config_missing_node_ids": [],
  "config_checked_count": 6
}
```

判定顺序：

1. P6.1 版本不一致 → `p6_version_changed`
2. P6.2.1 修订号不一致 → `p621_revision_changed`
3. 批次缺总指纹或节点数与快照不一致 → `config_snapshot_missing`
4. 任一节点缺 `params_json/config_sha256` → `config_snapshot_missing`
5. 批次总指纹与节点快照重算不一致 → `config_snapshot_invalid`
6. 当前 P1 同 `node_id` 节点缺失 → `node_config_missing`
7. 当前 P1 重算节点指纹与快照不一致 → `node_config_changed`

所有代码可并存；`stale_code` 取首个，供页面选择主文案。

## 六、状态解释

### 6.1 节点状态

| 状态 | 条件 | 是否进入订阅内容 |
| --- | --- | --- |
| `allowed` | 未命中关键词且四格式兼容 | 是 |
| `filtered` | 命中当前 P6.2.1 规则 | 否 |
| `unsupported` | 至少一种格式不能正确表达，或连接配置缺失 | 否 |

节点状态不因后续 P1 配置变化而改写；变化只影响批次 stale 判断。

### 6.2 批次持久状态

| 状态 | 说明 |
| --- | --- |
| `success` | 输出非空，四格式成功 |
| `partial` | 至少一个格式失败，另有成功 |
| `failed` | 四格式全部失败 |
| `empty` | 输出为空，四格式成功生成空结构 |

### 6.3 页面派生状态

| 状态 | 说明 |
| --- | --- |
| `not_generated` | 还没有批次 |
| `success/partial/failed/empty` | 批次未 stale，沿用持久状态 |
| `stale` | 版本、规则或连接配置已变化，禁止下载 |

一个历史批次即使持久状态是 `success`，只要当前配置不再匹配，页面和历史都会派生 `stale`。

## 七、API 字段

### 7.1 `GET /api/unified-subscription/summary`

新增/明确的字段：

- 顶层 `stale`、`stale_code`、`stale_reason`、`config_changed_count`、`config_missing_count`；
- `current.config_sha256`、`config_node_count`、`config_missing_count`；
- `batch.config_sha256`、`config_node_count`、`stale*`、`config_changed_count`；
- 每个节点 `config_sha256`、`has_config_snapshot`；
- 节点不返回 `params` / `params_json`。

### 7.2 `GET /api/unified-subscription/history`

每项新增 `stale_code/stale_codes/stale_reason/config_changed_count/config_missing_count`；不返回连接参数。

### 7.3 `GET /api/unified-subscription/formats/{fmt}`

新增 `stale/stale_code/stale_codes/stale_reason` 与 `batch.config_sha256`；内容仍是本批冻结内容。

### 7.4 `GET /api/unified-subscription/download/{fmt}`

- 批次 stale → HTTP 409，错误消息说明版本/规则/连接配置变化；
- 格式失败 → 409；
- 成功 → 附件下载，内容包含客户端连接所需参数。

### 7.5 Dashboard `unified_subscription`

新增 `stale_code`、`stale_reason`、`config_changed_count`、`config_missing_count`。不返回连接参数或指纹以外的敏感数据。

## 八、安全边界

- `np622_events.detail_json` 只记录批次号、格式状态和数量，不写 `params`。
- `np622_batches.status_reason` 不包含密码、UUID 或参数值。
- 普通节点表只展示 `server/port/protocol/score/labels/config_sha256`，不展示 `params_json`。
- 订阅文件内容按客户端要求保留连接参数；仅管理员登录后可预览/下载，未开放公网订阅入口。
- 日志和测试断言覆盖密码、UUID、Reality 公钥参数不进入 summary/history/dashboard/events/运行日志。
