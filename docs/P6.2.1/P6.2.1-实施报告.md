## 三、数据设计

### 3.1 `np621_rules`

关键词规则主表。`keyword_key` 为 `casefold()` 后的唯一键，用于阻止仅大小写不同的重复规则。

| 字段 | 说明 |
| --- | --- |
| `id` | 规则 ID |
| `keyword` | 原始关键词，保留大小写与中文 |
| `keyword_key` | 大小写折叠后的唯一匹配键 |
| `enabled` | 是否启用 |
| `created_at` / `updated_at` | 创建/修改时间 |

### 3.2 `np621_state`

单行运行状态表，记录规则修订号、当前来源 P6.1 版本、最近重算时间、重算触发方和六类汇总计数。`rule_revision` 每次规则变化加一，用作过滤结果失效判断。

### 3.3 `np621_results`

可替换的过滤预览缓存，不进入 P5/P6.1 历史。只保留“当前 P6.1 版本 + 当前规则”的结果，规则或来源版本变化时整体重建。唯一键为 `(category, node_id)`，同一节点跨类分别保存。

### 3.4 `np621_events`

P6.2.1 自身操作事件，记录规则新增、修改、删除、恢复默认和预览重算。与 P5/P6.1 事件表隔离。

## 四、匹配与过滤实现

匹配只对启用规则执行，覆盖：

1. 节点名称 `node_name`
2. 机场名称 `airport_name`
3. 服务器地址 `server`

采用 `casefold()` 后的包含匹配，因此英文字母大小写不影响结果。每个“规则 × 字段”命中都生成独立原因，记录规则 ID、关键词、字段代码、字段中文名和命中值；同一节点命中多个关键词或同一关键词命中多个字段时，全部原因保留。

节点级结果只有两种：

- `filtered`：至少一个启用关键词命中，不得进入允许下发预览。
- `allowed`：没有命中，进入允许下发预览。

六类分别计算，同一节点在标准类命中不影响其在 GPT 类的内部记录；某类命中仅把该类预览标记为 `filtered`。

## 五、重新计算链路

规则新增、修改、删除、启停、恢复默认均执行同一链路：

```text
规则写入 -> rule_revision + 1 -> 删除并重建 np621_results
        -> 重算六类 internal / allowed / filtered
        -> 更新 np621_state 和 np621_events
```

该链路不调用机场拉取、P2 健康检测、P3 业务检测、P4 评价/测速、P5 竞争或 P6.1 快照生成。规则变化不会新增 `np5_runs`，不会改变 `np5_state`/`np5_history`，不会新增 `np6_versions`，也不会修改 `np6_entries`/`np6_changes`/`np6_versions`。

当 P6.1 当前版本变化或规则修订号与缓存不一致时，下一次读取会自愈式重算预览缓存；这只更新 `np621_*`，不触发上游。

## 六、后台页面

页面路径为 `/#/final-filter`，菜单名为“最终过滤”。

- 顶部：规则即改即算提示、过滤预览标记、来源 P6.1 版本、刷新与重算。
- 边界说明：明确关键词过滤不参与检测、评分和竞争；允许下发仅为预览。
- 统计：内部智能优选、关键词过滤、最终允许下发、启用关键词。
- 规则区：新增、编辑、删除、启停、恢复默认、全部规则、每条命中节点数/原因数/涉及类别、展开后的命中节点与字段。
- 六类卡：六类内部、允许、过滤数量同屏；点击切换类别明细。
- 明细区：被过滤节点的节点名、机场、服务器、命中关键词与字段、过滤时间；允许节点名单、评分、P80、测速等级。
- 桌面 1910px 与移动 390px 均已验证；移动端导航 13 项可完整显示。

## 七、Dashboard

新增独立 `final_delivery` 块，不替换、不合并现有 `final_result` 与 `competition`：

- 内部智能优选数量
- 关键词过滤数量
- 最终允许下发数量
- 启用/全部关键词、命中规则数
- 来源 P6.1 版本、重算时间
- 明确“仅预览，未发布”“复用 P6.1，不新建”

## 八、默认规则

默认集合共 8 条，均为机场说明页/流量提示类常见词：

`剩余流量`、`过期时间`、`发布页`、`官网`、`Traffic`、`Expire`、`Official`、`Subscribe`

首次初始化且规则表为空时写入；用户可新增、修改、删除、停用，也可“恢复默认”重新写回这 8 条。默认集合只影响本批过滤预览，不影响任何订阅发布。

## 九、与既有机制的隔离

仓库已有两套旧关键词机制，本批未复用、未修改：

| 旧机制 | 所属链路 | P6.2.1 处理 |
| --- | --- | --- |
| `airports.filter_keywords` / `airport_filtered_nodes` / `fetcher.reclassify_airport` | P1 机场采集旁路 | 不读取、不写入、不改变行为 |
| `sub_filter_keywords` / `builder.apply_name_filter` / `/api/publish/preview` 的 `keyword_dropped` | 现有订阅分发 | 不读取、不写入、不改变行为 |

新功能只读取 `np6_versions` 与 `np6_entries` 的当前版本，写入仅限 `np621_*`。
