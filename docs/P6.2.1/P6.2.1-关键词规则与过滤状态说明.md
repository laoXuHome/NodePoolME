# P6.2.1 关键词规则与过滤状态说明

## 一、定位

关键词过滤是最终下发出口的独立关卡，不属于 P1 采集、P2 健康检测、P3 业务检测、P4 质量/测速、P5 竞争或 P6.1 快照。它只回答一个问题：当前 P6.1 六类内部优选中，哪些节点允许进入“最终下发预览”。

“允许下发”在本批仅是过滤计算结果，不代表订阅文件已生成、已发布或客户端可拉取。

## 二、规则模型

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | 主键 | 规则 ID，删除后不复用 |
| `keyword` | TEXT | 1–80 字符 | 原始内容，保留用户输入大小写 |
| `keyword_key` | TEXT | 唯一 | `casefold()` 后用于查重 |
| `enabled` | INTEGER | 0/1 | 是否参与匹配 |
| `created_at` | TEXT | 非空 | 创建时间 |
| `updated_at` | TEXT | 非空 | 最近修改时间 |

规则数量不设上限。允许中文、英文、数字和机场常用名称片段。空字符串、超过 80 字符、大小写折叠后重复均拒绝。

## 三、默认规则

默认集合 8 条：

| 关键词 | 设计意图 |
| --- | --- |
| 剩余流量 | 机场流量提示类节点 |
| 过期时间 | 到期提示类节点 |
| 发布页 | 机场发布页入口 |
| 官网 | 机场官网入口 |
| Traffic | 英文流量提示 |
| Expire | 英文到期提示 |
| Official | 英文官网提示 |
| Subscribe | 订阅入口提示 |

初始化条件：`np621_state.defaults_seeded = 0` 且规则表为空。写入后置 `defaults_seeded = 1`，不会在用户删空规则后自动回填；需要回填时使用“恢复默认规则”。

## 四、匹配规则

### 4.1 匹配字段

| 字段代码 | 中文名 | 来源 |
| --- | --- | --- |
| `node_name` | 节点名称 | `np6_entries.node_name` |
| `airport_name` | 机场名称 | `np6_entries.airport_name` |
| `server` | 服务器地址 | `np6_entries.server` |

`port` 不参与关键词匹配，只随结果展示。

### 4.2 匹配算法

```text
for rule in enabled_rules:
    key = rule.keyword.casefold()
    for field in (node_name, airport_name, server):
        if field 非空 and key in field.casefold():
            append hit(rule_id, keyword, field, field_label, value)
node.status = filtered if hits else allowed
```

性质：

- 只使用启用规则；停用规则保留但不参与匹配。
- 任一启用关键词命中即过滤。
- 包含匹配，不是前缀或全等匹配。
- 英文大小写不敏感；中文按原字符。
- 同一节点命中 N 个关键词、每个关键词命中 M 个字段时，记录 N×M 条原因，不合并、不覆盖。
- 不修改 `np6_entries.node_name`、`airport_name`、`server`、`node_id` 或任何 P6.1 身份字段。

## 五、六类独立状态

类别键固定为：

`standard`、`gpt`、`youtube`、`telegram`、`github`、`global`

每个类别分别保存同一 `node_id` 的结果，唯一键 `(category, node_id)`。因此：

- 同一节点可同时出现在六类中，形成六条独立预览记录。
- 节点在标准类命中关键词，只把标准类记录标为 `filtered`；其在 GPT、YouTube 等类别的内部记录不动。
- 六类计数分别汇总，不跨类去重。

| 指标 | 定义 |
| --- | --- |
| 内部优选数量 | 当前 P6.1 版本该类条目数 |
| 允许下发数量 | 该类中 `status=allowed` 的条目数 |
| 关键词过滤数量 | 该类中 `status=filtered` 的条目数 |

恒等关系：`internal = allowed + filtered`。

## 六、结果状态

### 6.1 `filtered`

条件：至少一条启用规则命中任一匹配字段。

记录内容：

- `node_id`、`node_name`、`airport_id`、`airport_name`、`server`、`port`
- `category`
- `hits[]`：规则 ID、关键词、字段代码、字段中文名、命中值
- `filtered_at`：本批预览计算时间

处理：不进入允许下发预览；仍保留在 P6.1 内部优选与 P5 竞争状态中，不删除、不淘汰、不改分。

### 6.2 `allowed`

条件：没有命中任何启用规则。

记录内容：同上节点身份、类别与评分附件字段；`hits=[]`、`filtered_at=null`。

处理：进入允许下发预览。该状态只在本批预览缓存中存在，不写回 P6.1，也不代表已下发。

## 七、重算与副作用矩阵

| 触发 | 重建 `np621_results` | 检测/测速 | P5 竞争 | P6.1 新版本 | 机场拉取 |
| --- | --- | --- | --- | --- | --- |
| 新增规则 | 是 | 否 | 否 | 否 | 否 |
| 修改关键词 | 是 | 否 | 否 | 否 | 否 |
| 删除规则 | 是 | 否 | 否 | 否 | 否 |
| 启用/停用 | 是 | 否 | 否 | 否 | 否 |
| 恢复默认 | 是 | 否 | 否 | 否 | 否 |
| 手动“重算预览” | 是 | 否 | 否 | 否 | 否 |
| P6.1 当前版本变化后首次读取 | 是（自愈） | 否 | 否 | 否 | 否 |

写入边界：

- 只写 `np621_rules`、`np621_state`、`np621_results`、`np621_events`。
- 不新增 `np5_runs`，不修改 `np5_state`/`np5_history`。
- 不新增或修改 `np6_versions`/`np6_entries`/`np6_changes`。
- 不调用 `fetcher`、P2/P3/P4 服务、P5 竞争服务、`final_results.snapshot`。
- 不调用 `subscriptions.builder`，不生成、不发布任何订阅。

## 八、缓存与历史

`np621_results` 是当前状态的可替换缓存，不保留历史。每次重算先清空再写入，因此：

- 规则回滚后不会自动恢复旧命中记录，而是按当前规则重新计算。
- `np621_state.rule_revision` 每次规则变化递增，作为缓存失效与页面修订号展示。
- `np621_state.p6_version_id/no` 记录本次预览所依据的 P6.1 版本；P6.1 产生新版本后，下一次读取会重建预览。
- P6.1 历史版本、P5 历史与 `np621_results` 完全解耦，过滤不改变任何历史快照。

| API | 方法 | 说明 |

| `/api/final-filter/rules` | GET | 全部规则及每条命中统计 |

页面 `/#/final-filter` 与 API 一一对应；Dashboard 只读取汇总，不提供规则写操作。

## 十、命中统计口径

每条规则返回：

- `hit_count`：去重后的命中节点数（按节点 ID 计，不按类别累计）。
- `hit_node_count`：与 `hit_count` 相同，保留显式语义。
- `hit_record_count`：全部“关键词 × 字段 × 类别”原因记录数。
- `matched_categories`：该规则命中到的类别键列表。

因此一个节点在四类同时命中同一关键词时，`hit_count = 1`、`hit_record_count = 4`，页面会显示“命中 1 个节点 / 4 条原因”。

## 十一、既有机制隔离

- `airports.filter_keywords`：P1 机场采集后节点名过滤，属于原始池旁路；本批不读取、不写入。
- `sub_filter_keywords` / `builder.apply_name_filter`：现有订阅分发过滤；本批不读取、不调用。
- P6.1 边界中的 `keyword_filter: false` 保持原值，表示 P6.1 自身仍未内置过滤；P6.2.1 以独立旁路实现。
