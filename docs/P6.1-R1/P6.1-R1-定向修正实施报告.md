# NodePoolME P6.1-R1 定向修正实施报告

## 一、修正结论

P6.1-R1 已修正最终优选快照的变化识别：快照不再只比较「竞争类别 + 节点 ID」，而是同时比较节点已保存的名称、机场 ID、机场名称、服务器地址和端口。任一有效身份信息变化都会生成新的有效版本。

本批版本：`v2.045`。

修正后：

- 节点改名仍属于原类别的保留节点，记录为 `retained`，不会误记为新增或移除；
- 同一节点换服务器、换端口、换机场或机场改名，均生成新版本；
- `np6_changes` 保留变化前后完整条目，并新增 `changed_fields` 字段变化摘要；
- 当前版本差异页对保留节点标注「信息变更」字段；
- 历史版本继续不可变，旧版本保留旧名称、旧地址、旧端口和旧机场；
- 原有六类隔离、有效空版本、无效轮次保护、无变化不建版本等规则保持不变。

## 二、缺陷根因

P6.1 原实现的成员签名只包含 `category` 和 `node_id`：

```text
六类 -> 节点 ID 列表 -> SHA-256
```

因此当 P1 节点仅改名或仅修改服务器、端口、机场信息时，签名不变，快照判定为 `unchanged`，系统继续沿用旧快照中的旧信息。

## 三、修正实现

### 1. 身份签名

快照签名升级为 `signature_version=2`，每个节点身份包含：

| 字段 | 说明 |
|---|---|
| `category` | 所属竞争类别，按类别分桶 |
| `node_id` | 节点 ID |
| `node_name` | 最终展示名称 |
| `airport_id` | 机场 ID |
| `airport_name` | 机场名称 |
| `server` | 服务器地址 |
| `port` | 端口 |

六类分别排序后序列化并计算 SHA-256。分数、成熟度、P80、速度变化仍不触发新版本，避免无意义的版本膨胀。

### 2. 旧版本兼容

v2.044 及更早版本使用「仅成员」签名。升级后不能因为签名算法变化而凭空生成一个重复版本，因此：

- 最新旧版本没有 `signature_version=2` 时，读取当前 P5 优选条目与该版本 `np6_entries` 的完整身份逐项比较；
- 身份完全一致：返回 `unchanged`，不生成版本；
- 身份有变化：生成新版本，并在新版本中写入 `signature_version=2`；
- 新版本之后直接使用新签名比较。

### 3. 变化记录

`np6_changes.detail_json` 结构扩展为：

```json
{
  "before": { "node_name": "旧名", "server": "1.1.1.1", "port": 443, "...": "..." },
  "after":  { "node_name": "新名", "server": "1.1.1.1", "port": 443, "...": "..." },
  "changed_fields": [
    { "field": "node_name", "label": "节点名称", "before": "旧名", "after": "新名" }
  ]
}
```

- 新增节点：`before=null`，`changed_fields=[]`；
- 移除节点：`after=null`，`changed_fields=[]`；
- 保留节点：`before` 与 `after` 均存在；身份有变化时 `changed_fields` 列出字段、旧值和新值。

API 的 `changes_of` 已把 `before`、`after`、`changed_fields` 提升为顶层字段，便于页面和验收脚本直接消费。

### 4. 页面展示

`/final` 版本差异区在保留节点下方展示：

```text
信息变更：节点名称、服务器地址、端口
```

具体前后值保留在 API 与 `np6_changes.detail_json` 中，不把长文本挤进窄卡片。

### 5. 自动调度

自动快照不再因为“来源 P5 run 相同”而跳过身份变化。判定顺序为：

1. P5 最近一轮必须为 `success`；
2. 计算当前身份签名；
3. 与最新版本比较；旧签名版本执行身份级兼容比较；
4. 无变化返回 `unchanged`；有变化生成新版本。
