# NodePoolME P6.1-R1 功能清单

## 一、版本基线

| 项 | 内容 |
|---|---|
| 基线版本 | P6.1 `v2.044` |
| 本批版本 | P6.1-R1 `v2.045` |
| 本批性质 | 定向修正，不新增阶段能力 |
| 施工范围 | 快照身份变化识别、差异记录、页面标注、测试与文档 |

## 二、新增与修正功能

| 编号 | 功能 | 状态 |
|---|---|---|
| R1-01 | 快照签名从「类别 + 节点 ID」扩展为「类别 + 节点 ID + 名称 + 机场 ID + 机场名称 + 服务器地址 + 端口」 | 已完成 |
| R1-02 | 节点改名生成新的有效版本，不误记新增/移除 | 已完成 |
| R1-03 | 节点换服务器地址生成新版本 | 已完成 |
| R1-04 | 节点换端口生成新版本 | 已完成 |
| R1-05 | 节点换机场 ID 或机场名称生成新版本 | 已完成 |
| R1-06 | 身份变化的保留节点记录 `changed_fields`、旧值与新值 | 已完成 |
| R1-07 | 历史旧版本保留原始名称和原始节点信息 | 已完成 |
| R1-08 | v2.044 仅成员签名兼容：身份无变化时不因算法升级生成重复版本 | 已完成 |
| R1-09 | 自动快照不再因同一 P5 run 跳过身份变化 | 已完成 |
| R1-10 | `/final` 差异页对保留节点标注「信息变更」字段 | 已完成 |
| R1-11 | 旧快照历史只读、不可改写、不可删除 | 保持 |
| R1-12 | 无变化重复快照返回 `unchanged` | 保持 |
| R1-13 | 六类独立计算新增、移除、保留 | 保持 |
| R1-14 | 有效空版本生成，不继承旧节点 | 保持 |
| R1-15 | `running` / `partial` / 无 P5 轮次拒绝建版本，不覆盖上一有效版本 | 保持 |

## 三、接口行为

| 接口 | R1 后的行为 |
|---|---|
| `GET /api/final/summary` | 使用身份签名计算 `pending` / `can_snapshot`，只读 |
| `GET /api/final/current` | 当前版本六类节点与差异；差异变化项含 `before/after/changed_fields` |
| `GET /api/final/versions` | 历史版本列表，只读 |
| `GET /api/final/versions/{id}` | 指定版本详情，旧版本保留原始信息 |
| `GET /api/final/diff` | 按类别返回新增、移除、保留；保留节点可查看字段变化 |
| `POST /api/final/snapshot` | 唯一生成入口；身份变化生成新版本，无变化 `unchanged` |

## 四、明确不做

- 不进入 P6.2 / P7。
- 不做关键词过滤或关键词管理。
- 不生成、不发布 Clash / Mihomo / Loon 订阅。
- 不修改订阅格式和发布入口。
- 不修改 P1 节点身份规则。
- 不修改 P5 六类状态、评分或竞争规则。
- 不设置固定优选数量，不补位。

## 五、与 P6.1 原功能的关系

R1 是 P6.1 的修正版本，不替代 P6.1 的六类优选、待定订阅池、版本快照、历史查询和 Dashboard 联动，只修正快照对“同 ID、不同节点信息”的识别盲区。
